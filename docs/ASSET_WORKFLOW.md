## 1. 原始素材只读保留

原片与 ZIP 留在仓库外。处理前建立备份和内容校验值，保存相对原路径。后续发现重复时先标记分组，不自动删除；同名文件也不能直接互相覆盖。

需要解压时先检查路径、符号链接、文件数量和解压体积，在独立目录进行。已有对应文件夹时先核对，避免重复解压或重新命名原文件。

## 2. 建立本地索引

为每份素材分配稳定编号，记录原相对路径、文件类型、大小、内容校验值、目录日期标签、可取得的拍摄时间及其来源、主题、核对状态和是否获准发布。原始路径只保存在本地。

日期来源分开存储：目录标签、EXIF、用户确认各占独立字段。修改时间、解压时间和文件创建时间不能直接当作拍摄时间。泰国与中国的时间差、设备时区和是否为导出副本都需要保留解释空间，不能机械改时区后覆盖原记录。

若用户说明与照片日期冲突，保留两份证据和人工选择，不静默改写历史。无年份时记录月日与 `year: null`，不要从本次归档年份推算。

## 3. 分组与目视复核

先按旅行、咖啡馆、礼物、日常和待确认分组，允许一张照片有多个标签。随后生成仅供本地看的缩略图联系表，检查方向、重复、模糊、人物与地点说明；视频单独检查时长、画面和声音。

完全相同文件可按内容校验值分组；相似照片只做候选组，交给用户挑选。文件名中的个人评价和情绪不直接成为公开说明。

## 4. 用户选片与说明

先保留全部原片，再选每个主题的代表素材。为每条记录明确以下状态之一：本地保留、网站候选、允许指定范围展示、允许公开、排除。

每组请用户补充两三句话：发生了什么、自己为何珍惜、希望观众看到什么。不要替用户编回忆。获准使用照片与获准使用人物姓名、生日或聊天文字是不同事项，记录实际同意范围。

## 5. 生成网站副本

只处理获准素材。HEIC 生成浏览器目标环境可用的图片副本，按页面需要提供缩略图、正文图和大图；MOV 的网站播放副本根据实际编码和目标浏览器另行决定，不靠扩展名判断兼容性。

副本采用中性编号命名，例如 `memory-001`；保留原路径到编号的对应关系在本地索引中。校验画面方向、色彩、清晰度和裁切，再去除不需要的 EXIF、位置及设备元数据。原片不作这些修改。

所有网站素材有明确宽高、说明、格式、文件大小和对应回忆编号。压缩参数通过照片质量和实际页面测试确定，当前不预设“已优化”的成绩。

## 6. 允许列表与发布检查

构建仅包含 `publicationApproval: true` 的内容和资源。不能把完整原目录拷入 `public/` 后只在页面里隐藏一部分；未被页面引用的公开文件也可能被下载。

发布前分别核对 Git 暂存文件、最终构建目录、网络请求与照片 URL。确认没有原片、私密索引、聊天记录、地理元数据、生日信息或本地绝对路径被误带入。

先向用户展示具体选片、文案、文件清单和发布目标，取得明确同意后再提交或推送涉及私人内容的文件。部署本身也按用户已授权的范围执行。

## 7. 回写项目记忆

确认后的事件更新 `MEMORY_TIMELINE.md`；设计选择更新 `DECISIONS.md`；场景与素材映射留在可维护的内容数据中。私密情绪补记只写入仓库外的本地档案，不随网站文档自动同步。
